# obsidian-claude-pkm

一套基于 Obsidian + Claude Code 的个人知识管理工作流。核心目标只有一个：**把"读过"变成"判断力"。**

写给想要**知识复利**的人——读过的东西能累积成自己的判断，而不是越积越多、越积越散。

---

## 为什么做这个

这套系统的核心是**两个循环**：

**学习循环**解决"读了用不上"的问题。读、AI 总结、自己总结——这些步骤产出的都是"理解"，但理解不等于能用。多了一步 `/train`，用 AI 苏格拉底式追问，把理解逼成**判断**（"我认为"而不是"作者说"）。判断才会留下，才能搬到新问题上，才能产生复利。

**计划循环**解决"学了没方向"的问题。从自我画像出发，推出成长计划，再由成长计划确定具体方向、生成子计划，成长计划和子计划共同推出每天的行动。学的方向不是随机捡来的，是从"我是谁"长出来的。

---

## 四层 = 四种角色

```
00_Self    我是谁      —— 整个系统的根
01_Plan    我现在做什么
           · 成长计划  —— 方向锚，"这段时间整体往哪走"，改得很少
           · 驱动层    —— 行动板，"今天做哪件事"，每次对话后更新
02_Inbox   档案        —— 原材料，只读，溯源用
03_Work    我的理解    —— 消化后的笔记、分析
           · *_plan   —— 各方向的子计划，由成长计划派生，和驱动层双链互联
04_Wiki    我的工具箱  —— 反复验证、可迁移的判断工具
```

关键区分：

- **02 / 03 是档案与理解**——停在"知道"层面。
- **04_Wiki 不是又一个档案，是工具箱**——像芒格的思维模型：少而精，每条都是一个**可执行的判断工具**（什么时候用 / 让你做什么判断 / 什么时候失效）。只有反复验证过、能搬到新问题上的判断才进得来；而且必须由你审核，AI 不能直接写入。

---

## 两个核心循环

这套系统能产生"知识复利"，靠的是两个**各自闭环**的循环。复利要成立得同时满足两件事，正好一个循环管一件：单位收益**不归零**，方向**不发散**。

### 循环一：学习 —— 让单位收益不归零

**四步走：**

1. **内容转 Markdown 存入** — 视频、播客、文章，统一转成 Markdown，放进 `02_Inbox` 或 `03_Work` 对应文件夹。
2. **AI 双重总结** — Claude 出两种总结：**结构化总结**（框架要点，方便查）和**叙述化总结**（逻辑串联，方便理解）。两种合起来，才能真正把内容吃透。
3. **带着问题和 AI 讨论 → 个人总结** — 边学边问、边聊边想，把消化后的理解用**自己的话**写成个人总结。
4. **`/train` 知识训练** — AI 反过来问你问题，把"我以为懂了"逼成"我真的能用的判断"。这是整套系统最核心的一步。

```
   ┌──────────────────────────────────────────────────────┐
   ↓                                                      │
 内容（视频/播客/文章）→ Markdown → 存入 02_Inbox / 03_Work   │
        │                                                 │
        ↓  AI 双重总结           → 产出「理解」（主语：内容）  │
        │                                                 │
        ↓  和 AI 讨论 → 个人总结  → 消化成自己的话           │
        │                                                 │
        ↓  /train 苏格拉底式追问  → 产出「判断」（主语：我）   │
        │                                                 │
        ↓  判断按形状分流：                                  │
        │    · 立场 / 修正       → 回写原笔记（## 训练洞见）  │
        │    · 可迁移判断 + 边界  → 04_Wiki 工具箱           │
        │    · 新关联            → 笔记之间建双链           │
        │    · 缺口             → 01_Plan 驱动层（下一步学啥）│
        │                                                 │
        └──── 下次从「被训练过的版本」出发 ＝ 复利 ────────────┘
```

读和总结产出的是"理解"，几周就忘；`/train` 把理解逼成"判断"，判断才会留下、才能搬到新问题上。下次学习从"被训练过的版本"出发，而不是从零开始——复利在这里发生。

### 循环二：计划 —— 让方向不发散

**自我画像催生成长计划，成长计划确定具体方向、派生出各方向的子计划（`*_plan`），再由成长计划和子计划共同推出驱动层。** 学的方向不是随机捡的，是从"我是谁"一路推下来的。

```
  自我画像 ─我是谁─────────────────────────● 几乎不动（方向真变了才改）
     │ 派生                                 ▲
     ▼                                      │ 攒够才校准
  成长计划 ─往哪走─────┬───────────────────● 阶段级校准
     │ 确定方向        │                    ▲
     ▼                 │（共同推出）         │ 每次对话更新
  *_plan ──────────────┴──→ 驱动层 ─────────● 流水账：记一行 + 抛缺口
 （各方向子计划）           （索引板）         ▲
                                │             │ 做完 → 状态同步回驱动层
                                └─ 选任务 ──→ 启动学习循环
```

这个循环是**双向**的，所以才闭环：

- **下行（派生方向）**：自我画像 → 成长计划 → `*_plan` → 驱动层 → 今天的任务。学什么不是随机捡，是从"我是谁"一路推下来的。
- **上行（现实回填）**：做完的事 → 流水账 → 驱动层 → 成长计划 → 自我画像，用真实做过的事反过来校准上面每一层。

关键不在"执行计划"，而在那条上行线：**你不是先定死自己是谁再去执行，而是在"做"里反过来把自己看得越来越清。** 自我画像因此是诚实的，不是空想的。而且**越往上改得越少**——流水账每次记，驱动层每天更新，成长计划攒够才动，自我画像几乎不动。

**两个循环在这里咬合**：计划循环选任务、交给学习循环；学习循环跑出的"缺口"又回到驱动层，成为下一步学什么。

## /train —— 这套系统的核心

`/train` 是一个 Claude Code skill，让 Claude 当苏格拉底式学习伙伴：不替你总结、不考你记忆，只问能逼出判断的问题。

> "你同意这个判断吗？有没有反例？"
> "这个逻辑再推一步会得到什么？"
> "这个框架什么时候会失效？"

**它和前几步的根本区别：前几步产出的每句话，主语是"内容 / 作者"；train 产出的每句话，主语是"我"。** 一条能用"我……"开头的，才是 train 的产物；"作者说……"开头的，是总结。

train 产物的五种形状——**立场、边界、修正、关联、缺口**——分别流向原笔记、工具箱、双链、驱动层四个去处。这一步是整套系统里唯一直接生产"判断力"的环节，前面都是给它供料。

**安装：**

1. 下载 [`skills/train/SKILL.md`](./skills/train/SKILL.md)
2. 打开 Claude Code → 上传 skill 文件
3. 在任意对话里输入 `/train` 即可启动

**触发方式：**

```
/train
来考考我
练习一下这篇笔记
基于这个文档问我问题
train me on this
```

## 配合 CLAUDE.md 使用

在知识库根目录放一个 `CLAUDE.md`，定义文件夹结构、命名规范、双链规范（双链一律用**文件名**而非路径，移动文件不断链）。Claude 读取后会自动把笔记存到正确位置，不需要每次手动指定路径。

本仓库的 `CLAUDE.md` 可以直接作为起点，按自己的习惯修改。

## 适合谁

- 想要"知识复利"——读过的东西能累积成自己的判断，而不是越积越散
- 在用 Obsidian，但笔记越来越多却用不上
- 读了很多书 / 播客，几周后只剩模糊印象
- 想用 AI 辅助学习，但不想让 AI 替你思考
