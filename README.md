# Frank's Knowledge System —— 系统设计文档

> 这份 README 是**给人看的设计文档**（设计理念、两个循环、关键决策）。
> AI 助手的**行为配置**是精简的 `CLAUDE.md`（只装会改变 AI 行为的规则）。
> 分工原则：**会改变 AI 行为的 → CLAUDE.md；解释系统给人懂的 → 这里。**

---

## 核心理念

这是 Frank 的个人知识系统，核心目标是积累知识、形成自己的框架与体系。

- **复利 = 把知识点彼此连起来、网越织越大**；越学，能接上的越多。
- **连接本身就是产物**——不强求每轮逼出一条「判断」。
- **人是主体，AI 只是辅助**——复利必须由 Frank 自己构建产生，长在他的脑子和笔记网里，不在 AI 的输出里。（这条是整套系统的第一性目的，见 `CLAUDE.md` 顶部。）

## 两个循环

### 循环一：学习（产出知识连接 + 新方向）

> 实际执行由 `vault-ingest` skill 承载（取文 → 双总结 → Opus 种子 → 收尾）。

```
   ┌──────────────────────────────────────────────────────────┐
   ↓                                                          │
内容（视频/播客/文章）→ Markdown → 存入 02_Inbox / 03_Work       │
        │（03_Work/ 有对应文件夹放那里；没有放 02_Inbox/）         │
        ↓  结构式总结 + 叙述式总结    → 产出「理解」（主语：内容）   │
        │                                                     │
        ↓  和 AI 讨论 → 个人总结      → 消化成自己的话            │
        │                                                     │
        ↓  Opus 列浅图：哪里可补充、哪里和库里已有内容有关联        │
        │                                                     │
        ↓  /tree 顺着浅图往深里探      → 长出新东西                │
        │                                                     │
        ↓  tree 产物按形状分流：                                 │
        │    · 新研究方向（一轮聊不完的坑）→ 01_Plan 驱动层        │
        │    · 关联为真               → 笔记之间建双链           │
        │    · 关联为假               → 改图（杀掉假连接也是产物） │
        │    · 待续没挖完             → backlog / 并进对应 _plan  │
        │    · 安静副产品：冒「我…」判断 → 回写原笔记 ## 训练洞见   │
        │                                                     │
        └──── 下次从「连得更密的版本」出发 ＝ 复利 ────────────────┘
```

**结构式总结**：按主题和概念对内容做整体拆解——是什么、有哪几条、分哪几层。目的是快速抓住内容的"形状"，方便检索和扫描。

**叙述式总结**：按原内容的实际顺序逐段走——第一节讲什么、逻辑怎么建立，第二节讲什么、论点怎么 prove，以此类推。忠实于原材料的展开路径，重点是每部分的论证过程。不是把要点改写成句子，是按顺序跟着原内容走一遍。

### 循环二：计划 —— 让方向不发散

**设计原则**：计划系统要干三件本质不同的事——**方向**（该往哪走）、**调度**（现在做哪件）、**记忆**（之前做到哪）。三件事各有合适的形状，别塞进同一个文件互相打架。而且贯穿一条铁律，和知识循环同构：**人是主体，AI 辅助——AI 让"挑"省力，但绝不替 Frank 挑。**

**五个元素，从慢到快：**

```
北极星（自我画像，几乎不动）
  └─ 成长计划（几个战略赌注 + 为什么，纯战略，攒够才动）
       └─ 各 plan（深执行细节 + 断点状态；大 plan 用双链挂子 plan）
            └─ 驱动层 = 一张薄全局板（每个活跃 plan 一行：断点 + 下一步 + 信号）
                 → Frank 扫板、对着战略自己挑今天干哪件
流水账（做完的成果，一行 + 双链，按时间排的产出索引）
```

- **方向**：北极星说"我是谁"，成长计划把它翻成几个战略赌注。学什么从"我是谁"推下来，不是随机捡。
- **调度（治"不知道每天干啥"）**：驱动层是一张**能一眼扫完的薄板**，不是一堵段落墙。Frank 扫板掌握全局、自己挑——**AI 只负责把板维护准，绝不替他挑/排**。深细节在各 plan 文件里，板上只放一行索引。
- **记忆（治"半成品丢失、隔代 AI 接不上"）**：每个没做完的 plan 身上挂一个**断点**（现在到哪 + 下一步）。它是**存档点**，不是成果：AI 收尾时自动写（半成品也写）、下次开场读它续上、做完即清。**成果归档（流水账）和断点存档是两回事**——前者等做完、永久；后者随时、用完即弃。这样 Frank 不必手动沉淀半成品，隔代对话也接得上。

**两个循环在驱动层咬合**：计划循环里 Frank 挑出的任务交给学习循环；学习循环跑出的「缺口」回到驱动层，成为下一步的候选。

## 关键设计决策

- **04_Wiki 暂停**：原为思维框架提炼层。退出主流程，因为**框架是大量实例反复撞出后的"晚期析出物"**，强行每轮索取只会逼出 n=1 的假框架。文件夹和已有几篇（如 `推导 vs 迭代`）保留不动，AI 不再主动往这里引导。等 Frank 自己说"这个想写成框架"时再启用。

- **train → tree，并重定位**：原 `/train`（苏格拉底式逐句逼问、把一篇榨成判断）已退役。现在的 `tree` 重定位为**对话分叉管理器**：一段会不断岔出新枝的讨论里，把每根岔枝轻量记下、挂住，护住主线，并维护一张"主线走哪、岔了哪些枝"的图。

- **判断降为安静副产品**：这套系统里"知识连接 > 逼出个人判断"。Frank 自己冒出的「我…」判断，逐字抓、不拔高，回写笔记的 `## 训练洞见`。

## 如何用到你自己身上（fork 后）

这个 repo 是 **Frank 真实系统的骨架**——`CLAUDE.md`、两个 skill（`skills/`）、这份设计文档，照搬即用。系统里**唯一私人的是 `00_Self` 那一层**（你是谁、要往哪走），其余全部从它长出来。所以把它变成你的，只要三步：

1. **Fork 下来**，把 `CLAUDE.md` 和 `skills/` 放进你的 Obsidian vault + Claude Code 环境。
2. **填个人层**：用仓库里的空白模板当起点——
   - `00_Self/自我画像.template.md`（北极星：你是谁、要去哪）
   - `00_Self/成长计划_plan.template.md`（你的几个战略赌注）
   - `01_Plan/驱动层.template.md`（你的行动板）

   照着填，填完把文件名里的 `.template` 去掉。
3. **跑两个循环**：丢链接进来走学习循环（`vault-ingest`）；扫驱动层、对着战略赌注自己挑今天干啥，走计划循环。

> 文档里的 **“Frank” 就是那个示范用户**——保留他，是为了让你看到一套**真在运转**的系统长什么样，而不是一份空模板。换成你自己时，把涉及个人的判断替换成你的即可。
