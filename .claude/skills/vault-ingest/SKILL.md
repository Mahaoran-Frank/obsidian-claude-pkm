# vault-ingest — 链接 → 原材料 → 双总结 → Opus 种子

这是把外部内容吸收进用户知识库的标准流水线，对应 `CLAUDE.md` 里的「学习循环」。四个阶段：

1. **取文**：链接 → 带时间戳的 Markdown 逐字稿，存成 `原材料_*.md`
2. **双总结**：结构式 + 叙述式，存成 `AI总结_*.md`（产出的是「理解」，主语是内容，不是替用户下判断）
3. **Opus 种子**：在总结末尾播一张浅图——哪里可补充、哪里和库里已有笔记有关联（双链候选）
4. **收尾清单**：流水账 + 驱动层（按 `CLAUDE.md` 的对话结束规则）

> 贯穿原则：**连接本身就是产物，不强求每轮逼出一条判断。**用户才是构建知识的人，你是辅助——不要过度总结、不要替他下结论。

---

## 这个 skill 会自己越跑越聪明 —— 先读状态，跑完写状态

它的"聪明"不是魔法，是**两个状态文件 + 你每次的推理**在复利。**每次开工前先读这两个文件，跑完按需写回：**

- `state/recipes.md` —— 已跑通的链接类型（域名→怎么取文）。命中就走快路径，不重新推理。
- `state/failures.md` —— 暂时搞不定的（卡在哪、缺什么）。这是成长清单，不是垃圾桶。

**开工第一步永远是 `Read` 这两个文件。** 它们让这个 skill 记得上次学到了什么。

## 阶段 1：取文（第一性原理 + 自我生长）

**第一性原理**：一个链接背后只有三种东西——
- ① 文字本来就在页面里（博客/公众号/Substack）→ 用 `WebFetch` 抓正文转 Markdown
- ② 音视频【有字幕】（B站AI字幕、YouTube CC）→ 抓字幕（最快最准最省）
- ③ 音视频【没字幕】→ 扒音频 → whisper 转写（慢，兜底）

②③ 由脚本统一处理：

```bash
bash "<本 skill 目录>/scripts/transcribe.sh" "<URL>" "<原材料目标文件夹>"
# <本 skill 目录> = 你加载本 skill 时拿到的那个目录（通常是 .claude/skills/vault-ingest）；别写死 ~/.claude
# 成功：最后一行打印 OUTPUT=<生成的md路径>
# 失败：打印 REASON=<原因>，退出非 0
# 想提速：在命令前加 WHISPER_MODEL=large-v3-turbo
```

### 路由逻辑（按顺序）

1. **先读 `recipes.md`**。链接命中已知配方 → 直接走那条路径。
2. **没命中（新类型）→ 第一性原理兜底**：判断它是 ①②③ 哪种。
   - 像纯文章页 → `WebFetch` 抓正文，自己整理成 `原材料_*.md`（套用下面的命名/头部格式）。
   - 像音视频 → 跑 `transcribe.sh`。
   - 拿不准 → 先跑 `transcribe.sh`；它若返回 `REASON=...yt-dlp 不认识...` 就说明是文章页，改走 `WebFetch`。

> **⚠️ 成本闸门（先确认再烧 token）**：当 ① 没有现成 recipe 可套，或 ② 要动用一个**未验证过的非常规方法**（反复换参数硬试、扒 RSS、手动绕风控等）时——**先把打算用的方法一句话讲给用户、等他确认再执行**，不要直接开跑、更不要无限重试。触发条件就这两个；边界是**仅限「猜错代价高」的岔口**（费 token / 不可逆 / 没把握）。recipe 命中的 routine 步骤照常快跑，**别逐步请示**（否则就退化成烦人的审问机）。

3. **跑通后，判断这个新类型会不会复发**（同平台、或属于用户常吃的形态：长访谈/播客/长文 → 大概率会）。
   - 会复发 → **提议**把"这次跑通的命令/做法"append 进 `recipes.md`，**等用户点头再写**（这是改 skill 自己，不擅自动）。
4. **跑不通（脚本退出非 0 或 WebFetch 取不到正文）→ 不许返回半成品糊弄**：
   - 把这条 append 进 `failures.md`：卡在哪一步、为什么、要以后能搞定需要用户提供什么（如 cookie / 换 RSS 入口 / 手动喂字幕）。
   - **当场告诉用户**，给出具体的下一步请求。等他补上 / 一起调好后，再把它从 failures 晋升进 recipes。

### 原材料文件：命名与去向（遵守 `CLAUDE.md`）

- 文件名：`原材料_<内容简称>_逐字稿.md`（脚本已按此命名）。
- 去向：`03_Work/` 有对应主题文件夹就放那里，否则放 `02_Inbox/`。**先扫一眼 `03_Work/` 各子文件夹再决定**。
- 头部保留：来源链接、转写方式（字幕 / whisper）、获取时间。
- 逐字稿是只读溯源材料，**不改动**。

## 阶段 2：双总结（产出「理解」）

新建 `AI总结_<内容简称>.md`，放在和原材料同一/最相关的文件夹。开头用双链指回原材料：`[[原材料_..._逐字稿]]`。

写**两种**总结，二者都要：

**结构式总结** —— 按主题和概念拆解内容的「形状」：是什么、有哪几条、分哪几层。目的是能快速扫描和检索。可以用小标题、表格、分层列表。

**叙述式总结** —— 按原内容的**实际顺序**逐段走一遍：第一节讲什么、逻辑怎么建立，第二节讲什么、论点怎么 prove……忠实于原材料的展开路径，重点是每部分的**论证过程**。不是把要点改写成句子，是跟着原内容走一遍。

> 两种总结互补：结构式给骨架（方便以后检索），叙述式留论证脉络（方便以后重走作者的思路）。

## 阶段 3：Opus 种子（浅图）

在 `AI总结_*.md` 末尾加一节，**这是这个 skill 最关键的增值**——为后续 `/tree` 提供起点。种子里播的关联**不一定为真**，明确标注待验证：

```markdown
## 三、浅图：可补充的方向 + 库里可能的关联（待 /tree 验证）

### A. 库里已有内容的关联（双链候选）
1. **<本文某点> ⇄ [[某篇已有笔记]]** —— 为什么能接上（一句话）。标 真/假/存疑。
   ...

### B. 可补充 / 一轮聊不完的坑（→ 可考虑进驱动层）
- <一句话带钩子的研究方向>
```

**怎么找双链候选**：用 `Grep`/`Glob` 扫 `03_Work/` 和 `02_Inbox/`，找概念能接上的笔记。双链一律用**文件名**：`[[笔记名]]`，不要用路径（见 `CLAUDE.md` 双链规范）。宁可多播几条候选连接，也不要逼出一条判断——**判假也是产物**，留给 `/tree` 逐条逼问。

> **安静副产品（不主动引导、不当目标）**：如果对话中用户自己冒出一条「我…」判断（立场/边界/修正/关联/缺口），用**他的原话逐字**抓一句，回写到对应笔记的 `## 训练洞见` 区块（没有就在文件末尾新建）。逐字留、不许提炼拔高。

## 阶段 4：收尾清单（按 `CLAUDE.md` 对话结束规则）

走完上面后，主动按顺序走一遍并把结果报告给用户（让他不用猜哪步做了）：

1. **流水账（必做）**：一句话总结今天做了什么，等用户确认后写入 `01_Plan/流水账.md`，格式：`MM/DD：[总结] → [[产出文件1]] [[产出文件2]]`
2. **驱动层（必做）**：本次改动过的 `_plan` 子笔记，把驱动层里对应行的状态同步过来。新冒出的缺口可提议新增，但**增删取舍是用户的活，不替他判断**。
3. **成长计划（按条件触发）**：只在「某 Phase 做完」或「缺口大到改变方向」时**提议**改 `00_Self/成长计划_plan.md`；否则明确说「成长计划无需改动」。

## 速查

- 转写脚本：`scripts/transcribe.sh <URL> <输出目录>`（环境变量 `WHISPER_MODEL` 调速/调准）
- 依赖：`yt-dlp`、`ffmpeg`、`whisper-ctranslate2`（fork 后需自行安装，如 `brew install yt-dlp ffmpeg`；只吸收纯文章用不到）
- 状态文件：`state/recipes.md`（成功沉淀）、`state/failures.md`（失败待升级）
- 范例标准：一篇跑通的 `AI总结_*.md` 应当**结构式 + 叙述式 + 浅图**三段齐全。
